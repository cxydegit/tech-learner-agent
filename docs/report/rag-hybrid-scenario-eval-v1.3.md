# 混合检索：量化评估 + 四个修复的验证 v1.3

> **本版（v1.3）在 v1.2 基础上新增第四个修复：词法一致性软重排（轻量 rerank）。**
> 版本脉络：v1.0 纯评估 → v1.1 分词 + coach 门槛（含错误诊断）→ v1.2 修正诊断 + 零分填充修复 → **v1.3 词法重排**。
> 数据说明：评测脚本未随仓库分发，下表为当时实测记录。

---

## 一句话结论

**v1.2 修完零分填充 bug 后，专有名词已 100% 全中，但存在一个排名瑕疵：`RoPE` 这类裸缩写查询，dense 把无关的 rag-架构模式 排第 1（通篇无 RoPE，纯 embedding 噪声），正确笔记只能排第 2。** 本版加了一个轻量 rerank 解决它：**整体 MRR 从 0.897 提到 0.920，专有名词 MRR 从 0.881 提到 0.964，其他场景零回退**——而且全程零新依赖，只多了 3 个配置项和 1 个纯函数。

---

## 解决什么问题

修完零分填充后，`RoPE` 的 transformer 笔记进了答案（第 2 名），但 `rag-架构模式` 还是第 1（dense 语义榜第 1、sim 0.541，可它通篇没有 RoPE）。RRF 无权重，语义榜第 1 和关键词榜第 1 打平，谁先插入谁排前。这是 dense 对裸缩写/专有名词的固有噪声，光修 bug 不够。

## 方案：词法一致性软重排（triggered lexical re-rank）

**原理**：RRF 融合后，按「查询词在候选块里的覆盖率」加分——含 `RoPE` 的块（覆盖率 1.0）压过零词法重合的 `rag-架构模式`（0.0）。

但这套方案连续踩了两个坑，逼出了最终设计：

1. **朴素覆盖率被中文单字分词灌水**：`RedisJSON 能做什么` 切成 5 个词，`能/做/什/么` 是烂大街中文字，几乎每块都有，覆盖率被灌到 0.6，把真含 `redisjson` 的 redis-stack 反而压低到第 6。
   → **修法**：覆盖率按词在候选集上的 mini-idf 加权，罕见词（redisjson/rope）权重大、常见中文字权重趋近 0。
2. **即使 idf 加权，对概念查询仍误伤**：`React 18 有哪些核心变更`、`Redis 五种基础数据结构怎么选` 等从第 1 掉到第 2——覆盖率重排对"罕见词型"查询有用，对"概念查询"有害。
   → **修法**：加触发条件，**仅当 BM25 正命中 ≤ 3 篇笔记（罕见词型查询）才重排**。实测分界非常干净：命中 ≤3 篇时重排只改进或持平（14 条 exact 全在此列），≥4 篇时全是回退。

**最终设计**：
- `domain/hybrid.py::lexical_rerank`（纯函数）：idf 加权覆盖率，`rerank = rrf × (1 + w × 覆盖率)`，w=0 等价纯 RRF。
- `adapters/vector.py::hybrid_search_knowledge`：RRF 后，当 `BM25 正命中笔记数 ≤ QA_RERANK_MIN_HITS(3)` 时应用。
- `config.py`：`QA_RERANK_LEXICAL`（开关，默认 true）、`QA_RERANK_LEXICAL_W`（权重 0.5）、`QA_RERANK_MIN_HITS`（触发阈值 3）。

## 效果（v1.2 → v1.3）

| 指标 | v1.2（零分填充后） | v1.3（+词法重排） |
|---|---|---|
| 整体 hit-rate / MRR | 98% / 0.897 | 98% / **0.920** |
| 专有名词 hit-rate / MRR | 100% / 0.881 | 100% / **0.964** |
| 常规问答 / 联想 / 口语化 / 判别 | 100% / 1.0 / 90% / 100% | **零回退**（同上） |

具体修复的排名（均为真实代码路径验证）：
- `RoPE`：第 2 → **第 1**（正确笔记压过无 RoPE 的 rag-架构模式）
- `PagedAttention`：第 2 → **第 1**
- `KV Cache`：第 3 → **第 2**

224 个单测通过（新增 lexical_rerank 3 个用例）。

> 诚实标注：`注意力机制怎么加速优化` 一例（BM25 命中 17 篇，属概念查询）原本可借重排从第 2 升第 1，因触发条件不重排而保持第 2——这是"零误伤"的代价，可接受。

---

## 结论与建议

1. **轻量 rerank 值得做**（本版已落地）：一个纯函数 + 触发条件，专有名词排名质量显著提升、整体 MRR 上涨、无回归。相比引入 cross-encoder reranker，这套方案零新依赖、效果已达标；**reranker 仍留在 backlog**（若未来语料变大或需要语义级判别再上）。
2. **四个修复的完整故事**：分词点号不拆（`FT.SEARCH` 能搜到）→ coach 门槛重标定（误注入 0/6）→ 零分填充过滤（专有名词 79%→100%）→ 词法软重排（排名 0.881→0.964）。其中零分填充和词法重排都是"实测数据逼出真因"的调试案例。
3. 回归看板不变：改检索/切词/阈值后跑 `--retriever both`。
