# 上下文装配预算 A/B 实验（生成层）

> 定位：上一份生成层报告（忠实度基线）把「要点未覆盖」逐条归因，最大一类落在**装配环节**——支撑笔记进了材料，但要点那句话被"每篇 ≤3 段 × 500 字"切在门外。本份量的是：**把交付预算放宽，到底有没有用、代价多大**。
> 数据说明：评测脚本与黄金集未随仓库分发，下表为实测记录，**涉及笔记的表述已匿名化**（原为个人知识库的文件路径）。
> 运行时间：2026-10-10 ｜ 被测对象：生产问答管道（**两臂同批跑、共享同一份检索结果**，唯一差异是装配参数）。
> 性质：**单次成对实验**，不是长期回归闸门。结论以"机制是否成立"为主，"涨了多少"为辅——后者受样本量限制，见「诚实边界」。

## 一句话结论

1. 交付预算「5 篇 × 每篇 3 块 × 500 字」→「6 篇 × 不限块 × 500 字」：**要点覆盖 154/173 → 159/173（+5）**，逐条配对 **6 赢 2 输**，符号检验 **p = 0.289，不显著**。
2. **那个 +5 不能直接当结论**。把 7 个「赢点」逐条按「支撑内容在不在基线材料里」分类：**只有 4 条是材料带来的，3 条是生成随机性**；3 个「输点」的支撑内容在两臂材料里都在，同样是随机性。
3. 站得住的是**机制**：那 4 条要点的支撑内容确实从"不在材料里"变成"在材料里"（贴合度 0.13~0.25 → 0.60~0.93）。**这一步是确定性的、不依赖模型的发挥**；随机的是模型有没有把它说出来。
4. 两个变量各自值多少（2×2 因子分解，173 条要点，**零 LLM 调用**）：**去掉每篇块数上限 +11 条（39 字/条）；篇数 5→6 只 +2 条（146 字/条）；交互项 0**。
5. 代价（真实 token，来自调用日志）：生成 prompt 平均每题 **1540 → 1905（+365，+24%）**；回答长度持平（803 → 818 字）。**没有系统性变差**——要点全覆盖的题 41 → 45、编造说法 6 → 3、拒答 7/7。
6. 顺带查出两条独立缺陷（**未修**）：交付片段里 **15.4% 是「标题+日期+标签」的纯元数据块**（68% 的题至少浪费一个名额）；基线里至少 1 条「未覆盖」是生成随机性、不是稳定缺陷。

## 背景：为什么怀疑装配环节

基线报告给出 18 条未覆盖要点，最大一类判为「支撑笔记进了材料、但要点那句话不在」。本次在此基础上用**逐级放开限制的反事实**重做归因——同一批召回命中，用生产组装函数依次放开「片内 500 字」「每篇块数」「篇数」三个限制，看要点与材料片段的贴合度在哪一档越线：

| 卡在哪 | 条数 |
|---|--:|
| 5 篇交付上限（笔记在召回池里、排第 6~8 名被切） | 7 |
| 每篇 3 块上限（含要点的块在该篇第 4~8 位） | 3 |
| 片内 500 字截断（块进了材料、要点在后半段） | 1 |
| 材料里本来就有（生成侧） | 1 |
| 召回池里就没有（检索侧，装配改不了） | 6 |

**重建归因时发现该方法本身的噪声**：同一配置重跑，有一条要点的覆盖状态会变（见「诚实边界」）。所以上表的"条数"是**上界估计**，不是精确计数——这也决定了本次实验必须做成两臂同批的配对设计，而不是拿新旧两份快照比对。

## 实验设计

| 项 | 做法 |
|---|---|
| 两臂 | **A（基线）** = 5 篇 / 每篇 3 块 / 片内 500 字；**C（候选）** = 6 篇 / 每篇不限块 / 片内 500 字 |
| 同批 | 两臂在**同一次运行**里依次跑完 60 题，消除生成温度带来的批次差异 |
| 共享召回 | 两臂吃**同一份检索命中**（先落盘、再复用），臂间唯一差异就是那三个装配参数 |
| 判定口径 | 与前一份生成层报告**完全一致**：同一评审提示词、温度 0、同一模型、同一分层报数——改一个字就不可比 |
| 上下文层判据 | 「参考要点与材料片段的贴合度 ≥ 0.5」视为材料里有支撑。**校准**：被覆盖要点 92% 过线、未覆盖要点 6% 过线（唯一过线那条经人工复核为生成侧漏答）。它量的是"材料够不够"，**不调用模型，因此完全可复现** |
| 保真性核验 | A 臂的材料字数与片段数**与基线快照逐题完全相同**（说明共享召回 + A 臂精确复现了生产行为） |

## 结果

### 材料层：2×2 因子分解（零 LLM 调用）

固定片内 500 字，单独与联合地放开另两个变量：

| 配置 | 上下文召回 | 命中条数 | 材料字数均值 | 平均块数 |
|---|--:|--:|--:|--:|
| 5 篇 / 3 块（A） | 82.1% | 142 | 1943 | 9.9 |
| **5 篇 / 不限块** | **88.4%** | **153** | 2377 | 12.5 |
| 6 篇 / 3 块 | 83.2% | 144 | 2235 | 11.4 |
| 6 篇 / 不限块（C） | 89.6% | 155 | 2702 | 14.2 |

| 主效应 | 收益 | 代价 | 单位成本 |
|---|--:|--:|--:|
| **去掉每篇块数上限** | **+11 条** | +434 字 | **39 字/条** |
| 篇数 5→6 | +2 条 | +292 字 | 146 字/条 |
| 交互项 | 0 | — | — |

**去块数上限的总收益是加篇数的 5.5 倍，单位成本低 3.7 倍。** 但两者**不是替代关系**：生成层实测的 4 条真实收益里，2 条由块数上限修复（讲 RAG 与微调的笔记、讲 Python 装饰器的笔记），2 条由第 6 篇修复（讲 LLM 推理优化的笔记被整篇挡在门外）。留 6 篇的理由不是总量，而是**它修的是"整篇笔记进不来"这一类，没有别的参数能替代**。

### 生成层：配对结果

| 指标 | A（5篇/3块/500字） | C（6篇/不限块/500字） | 差异 |
|---|--:|--:|--:|
| **要点覆盖** | 154/173（89%） | **159/173（92%）** | **+5** |
| 忠实度 | 428/434（99%） | 472/475（99%） | — |
| 标注推断 | 69 条 | 65 条 | −4 |
| 编造说法 | 6 条 | 3 条 | **−3** |
| 拒答正确 | 7/7 | 7/7 | — |
| 引用合规 | 235/235 条引用 | 236/238 | 见下 |
| 材料字数均值 | 2414 | 3203 | +33% |
| 回答长度均值 | 803 字 | 818 字 | +2% |
| 逐条配对 | — | 赢 6 / 输 2 / 平 52 | p = 0.289 |

分层（要点覆盖）：常规 90% → 94%｜边界长尾 92% → 95%｜不可回答（拒答）6/6 → 6/6｜历史事故 67% → 67%。

**引用合规的 2 条逐条查过**：一条是模型把拒答理由写成了「（来源：本次检索到的全部片段均属…，无 Docker 相关内容）」，被合规检查当成引用抓进来——**检查器的伪阳性**；另一条是路径里的日期写错了一个不存在的文件——真错，但很轻。

### 逐条归因：7 个「赢点」里只有 4 个是真的

**判据**：C 的材料是 A 的超集（同一批召回 + 更宽的上限 ⇒ 只增不减）。所以如果某个赢点的支撑内容在 **A 材料里本来就对得上**，这个赢就与材料无关。

| 题（主题） | 新增覆盖的要点 | A 材料贴合 | C 材料贴合 | 判定 |
|---|---|--:|--:|---|
| RAG vs 微调 | 复杂场景常用两者结合 | 0.25 | 0.62 | ✅ 真实材料收益 |
| Python 装饰器 | `*args/**kwargs` 原样转发 | 0.14 | 0.71 | ✅ 真实材料收益 |
| PagedAttention | 解决自回归生成时的显存碎片化 | 0.13 | 0.93 | ✅ 真实材料收益 |
| PagedAttention | 与 KV Cache 同属推理加速 | 0.13 | 0.60 | ✅ 真实材料收益 |
| Decoder-only 为什么主流 | 三种主流架构变体 | **0.90** | 0.90 | ❌ 生成随机性 |
| Deep Agents 组件 | 由 LangChain 提供的框架 | **0.88** | 0.88 | ❌ 生成随机性 |
| skill 目录 | 同名冲突项目级覆盖用户级 | **0.73** | 0.73 | ❌ 生成随机性 |
| 类型提示 | 运行时不强制校验 | 0.08 | 0.08 | ⚠️ 存疑（两臂材料都无支撑） |

**3 个丢失的要点同理**：f-string 用法、蛇形命名、Agent 组合方式——这三条的支撑内容在 **C 材料里也都在**（0.71 / 0.67 / 1.00），不可能是材料变化导致的。

**最干净的一条（PagedAttention）**：A 臂的回答是「**笔记里没有记录 PagedAttention 相关内容**——检索到的片段中没有出现这个词」；C 臂补上那篇笔记后，回答变成「PagedAttention 与 KV Cache 管理归在推理加速方向下，要解决的是自回归生成时的显存碎片化和重复计算问题」。**同一个问题，从"库里没有"变成答得出来。**

## 代价（真实 token，来自调用日志）

| | A | C | 变化 |
|---|--:|--:|--:|
| **生成 prompt** | 92,413 | **114,293** | **+21,880（+23.7%）＝ +365/题** |
| 生成 completion | 32,698 | 34,471 | +1,773（+5.4%） |
| **生产侧合计** | 125,111 | **148,764** | **+18.9%（+394/题）** |
| 评审 prompt + completion（仅评测开销） | 184,276 | 208,421 | +13.1% |

回答长度 803 → 818 字：**模型没有因为材料变多而变啰嗦**。材料字数 +33% 而 token 只 +24%，因为中文的字符/词元比约 2:1。

## 护栏：没有系统性变差

| 指标 | A | C |
|---|--:|--:|
| 要点全覆盖的题 | 41 | **45** |
| 部分覆盖的题 | 9 | 6 |
| 零覆盖的题 | 3 | 2 |
| 编造说法 | 6 条（涉及 6 道题） | **3 条**（涉及 3 道题） |
| 拒答正确 | 7/7 | 7/7 |
| 回答长度均值 | 803 字 | 818 字 |

覆盖率变差的只有 2 题，而这两条要点的支撑内容在**两臂材料里都在**（0.71 / 1.00）——不可能是"材料变多挤掉的"。

## 诚实边界

1. **总量增益不显著，别当结论用。** 6 赢 2 输、p = 0.289；只看那 4 条真实收益（4 赢 0 输），p ≈ 0.125 仍不显著。60 题的样本量下，**这个实验能证明"机制成立"，不能证明"提升显著"**。
2. **随机与"稀释"分不开。** 那 3 条丢失的要点，其支撑内容在两臂材料里都在，与"生成随机性"一致；但要严格排除"材料变多稀释了注意力"，需要同一配置重跑多轮——本次只跑了一轮。所有总量指标（全覆盖题 +4、编造 6→3、拒答 7/7、回答长度持平）都**不支持**稀释假设。
3. **基线的归因本身有噪声。** 重跑时确认至少 1 条要点的覆盖状态会变（同一配置、同一题目）。这意味着基线报告里"18 条未覆盖"中有一部分并非稳定缺陷——**凡是要拿来当修复依据的条目，都应先验一次复现性**。
4. **历史事故层没有改善**（67% → 67%）。该层的失分主要是检索侧（要点所在内容根本没进召回池），装配预算放宽救不了它。
5. **两条缺陷本次未修**，且其中一条比本次改动更值得做：交付片段里 **15.4% 是「标题+日期+标签」的纯元数据块**（相似度天然高、零内容），**68% 的题至少被它占掉一个名额**。

## 决策

**采用 C：`QA_MAX_GROUPS` 5 → 6，`QA_SNIPPETS_PER_NOTE` 3 → 不限。**

理由：机制经两臂同批验证；护栏指标无一退化（编造还降了一半）；代价是每次提问多约 365 个 prompt 词元。**片内 500 字截断保持不变**——单独放开它只多召回约 1 条要点，却会同时改变教练注入路径的共用参数，不值。

## 复现

两臂一次性跑完（120 次生成 + 120 次评审），召回共享，逐条快照含两臂全部条目（`arm` 字段区分）与每条的完整材料、回答、评审判定。上下文层的 2×2 分解与逐条归因**不需要任何模型调用**，由落盘的原始召回重算，因此可反复核对。

## 遗留

- **纯元数据块占 15.4% 的交付片段**（68% 的题受影响）——独立、确定、干净的缺陷，下一处该修的就是它。
- **片内 500 字截断**与**召回深度**未扫；取件篇数的反事实显示 8 篇起召回不再增长。
- 历史事故层的检索侧缺口（要点内容不进召回池）尚未归因到具体机制。
