# 问答忠实度基线（生成层）

> 定位：前面几份报告量的是**检索层**（材料找没找到）；本份是**生成层**的第一份——回答有没有编造、该拒答有没有拒答、参考要点覆盖够不够。
> 数据说明：评测脚本与黄金集未随仓库分发，下表为实测记录，**涉及笔记的表述已匿名化**（原为个人知识库的文件路径）。
> 运行时间：2026-10-07 ｜ 被测对象：生产问答管道（与线上同一入口、同一提示词、同一配置）。
> 修订：**v1.1（2026-10-08）**——P1-2 人工复核结论入档；1 条要点的覆盖判定经补判恢复（154/173 → 155/173）；分层表「标注推断」分列数勘误；发现 2 的两组占比统一为汇总口径（原为逐题平均）。**v1 保留不删**，本文件为其修订版。

## 一句话结论

1. **忠实度 99.8%（427/428 条事实性说法有材料支持）**；按评审口径的「无据说法」仅 **1 条**（1/58 条题），经人工复核为**「挂源不严谨的合理外推」——真编造 0**。另有 63 条（占全部说法 13%）被模型**自己标注为「我的总结/推断」**——按提示词这是合规行为，单列不计入分母。
2. **材料缺位时，模型的行为是「标注推断」而不是编造**：参考要点覆盖为零的 3 条题，其 13 条说法里 6 条（46%）被标为推断；而覆盖≥50% 的 50 条题只有 12%（53/458）。这是本次最值得写下来的一条：检索失败没有直接变成幻觉，而是变成了"带标记的不确定"。
3. **拒答 100% 正确（7/7）**：包括两条**同域陷阱**（库里满是 Redis 笔记时问 Redis 持久化；提到 Docker 但只出现过"用 Docker 跑 Redis"时问 Docker Compose）——模型没有拿相邻材料凑答案。
4. **要点覆盖 90%（155/173）**，最弱的一层是「历史事故题」67%。**18 条未覆盖要点逐条归因**：装配截断 **9 条**（支撑笔记进了材料、要点那句话被"每篇 ≤3 段 × 500 字"截掉）、检索漏召回 **8 条**（笔记压根没进材料）、生成侧漏答 **1 条**（材料里有那句话、模型没答那半句；且经人工复核，该要点属"身份描述"、用户提问并未要求——**要点设计边缘，不是模型的实质缺陷**）。**最大的那一类不是模型，也不是检索，而是两者之间的装配环节**——这正是三层里此前完全空白的一层。

## 主要发现

### 1. 唯一的 1 条「无据说法」：人工复核为"合理外推 + 挂源不严谨"，真编造 0

评审口径下唯一一条"无材料支持、也未标注推断"的说法，来自「Python 数据结构与 Java 集合怎么对应」：材料写的是「List 无需声明泛型」，回答延伸成「字典本身也不要求声明泛型」——而且给这句**挂了来源标注**，但那篇笔记只对 List 说过这句话。

人工复核（挑最可能判错的 8 条逐条对照材料原文）的结论：**外推本身合理且正确**（dict 与 List 是同一张对照表里的兄弟结构，Python 内置容器都不要求声明泛型），问题出在"挂源不严谨 + 没标推断"——**性质是来源标注问题，不是编造**。

这条仍保留在指标里：忠实度量的是"每句是否可追溯到材料"，"合理但无据"正是指标要抓的东西。本报告自此区分两个口径——**无据说法（评审判定）＝1 条；真编造（人工复核）＝0**。

### 2. 材料缺位 → 进入"标注推断"通道（46% vs 12%）

| 分组 | 条数 | 要点覆盖 | 「标注推断」占该组全部说法的比例 |
|---|--:|--:|--:|
| 覆盖 ≥50% 的题 | 50 | 94% | 12%（53/458） |
| **覆盖 = 0 的题** | 3 | 0% | **46%（6/13）** |

三条零覆盖题的回答形态一致：先说明材料里是什么，再把自己的补充**显式标成推断**（例："检索到的片段讲的是 Redis 的角色与降本，没有部署与运维配置（我的推断）"）。检索漏召回因此没有升级成幻觉。
**但要留个心眼**：这也是一个可被"取巧"的通道——如果模型把所有内容都标成推断，忠实度分母就会缩小。当前 13% 的占比是健康的，报告口径里同时保留"标注推断占比"这一列就是为了盯住它。
（v1.1 说明：两组占比统一为"该组推断条数 ÷ 该组全部说法条数"的汇总口径；v1 用的是逐题占比再平均，会被只有 1 条说法的小回答放大。）

### 3. 拒答正确率 100%，含两条同域陷阱

7 条拒答题（不可回答 6 + 历史事故层 1）全部照实说明"笔记里没有记录"，**误答 0**。其中两条是刻意设计的高难场景：
- 「Redis 的持久化 AOF 怎么配置」——库里有一批 Redis 笔记，检索必然返回 Redis 材料；
- 「Docker Compose 怎么编排多个容器」——"Docker" 在库里出现过（Windows 那篇推荐"用 Docker 跑 Redis"）。

模型没有把相邻材料当成答案。另有 1 条（Redis 集群分片配置）多说了几句材料里的 Redis 定位，但同样明确说明"没有集群分片的内容"。

### 4. 未覆盖要点的三类归因：**装配截断最大（9 条），不是模型也不是检索**

把 **18 条**未覆盖要点逐条对照「支撑笔记有没有进材料」与「要点那句话在不在材料里」：

| 归因 | 条数 | 判据 | 例子 |
|---|--:|---|---|
| **B 装配截断** | **9** | 支撑笔记**进了材料**，但要点那句话**不在** | 类型提示那条题：笔记在材料里，但「不强制运行时校验 / 可配 mypy 静态检查」这两句被切掉；装饰器那条题同理（`*args/**kwargs` 原样转发一句缺失） |
| C 检索漏召回 | 8 | 支撑笔记**压根没进材料** | 见下两条 |
| A 生成侧漏答 | 1 | 材料里有那句话，模型没答 | 「LangChain 提供的智能体框架」这半句——人工复核认为它是笔记的"身份描述"、用户提问（"有哪些核心组件"）并未要求，属**要点设计边缘**；v1 曾计入的第 2 条系"干扰项"误入分母，属标注缺陷，已修正 |

**B 类的机制是确定的**：材料装配对每篇笔记只取**最靠前的 ≤3 段、每段 ≤500 字**——短笔记里排在后面的要点，随笔记进入材料却进不了模型眼前。这一层此前没有任何指标（三层模型里的"上下文层"一直是空白），本次第一次量到它，而且它是**当前最大的一类缺口**、修法纯确定性（不需要动模型与提示词）。

### 5. C 类（检索漏召回）：两条题、两种已知毛病

| 题 | 期望材料 | 实际拿到 | 归因 |
|---|---|---|---|
| 加速手段三件套（FlashAttention / KV Cache / PagedAttention 各解决什么） | 「LLM 工程实践」笔记 | 该笔记不在材料内 | **多词长问句**：同一术语的单词查询在检索层是命中的，串成一句自然语言问句就漏 |
| AI 回复每次都不一样，我笔记里有讲吗 | 「LLM 应用开发陷阱」笔记（Temperature=0 的伪确定性） | 该笔记不在材料内 | **口语问法 vs 术语笔记**：与检索层 fuzzy 场景的漏召回同源，两处互相印证 |

处置上，模型对这两类都**如实说"笔记里没有记录"并把自己的补充标成推断**（见发现 2），所以缺口只体现在覆盖上，没有升级成幻觉。

## 已知边界与遗留（诚实清单）

1. **评审偶发失败（而非判定漂移）**：温度 0 下仍出现过评审调用返回无法解析 / 空内容（1 条题连续两次失败），该条按"未判"整条剔除、不进指标，补上重试后单独补判成功；早期另有过一类"覆盖下标以字符串形式返回未被兼容"的解析缺陷（已修，相关条目在其后的重判中恢复）。覆盖类指标在小样本薄层（单层 6 条）仍有 ±1 题量级的粒度限制，逐条结论以人工复核为准（评审原始输出已随快照留档）。
2. **评审已做定向复核，未做随机抽样校准**：挑"最可能判错"的 8 条逐条人工对照，2 处需修正（1 条无据说法的性质与命名、1 条要点的设计，均已在 v1.1 更新），其余判定成立；**随机样本的评审-人工一致率（κ）未测**，留待需要对外的场合（盲评表与计分工具已备）。另注意评审与生成是**同一模型**，存在自评偏好的残余风险。
3. **生成温度 0.5，重跑答案会不同**：忠实度数字本身带采样噪声；做"改前/改后"对比时必须**成对比较**（同一批题逐条算胜负），不能只比两个聚合数。
4. **「标注推断」通道的取巧风险**（见发现 2），当前 13% 属健康区间。
5. **拒答题的"如实"判定靠措辞**：判据是"是否明确说笔记里没有"，不检查它有没有在"没有"之外补充了外部知识——补充部分只体现在忠实度里。
6. 60 条是标准版下限；薄层（不可回答 6 / 历史事故 6）单条权重 17%，报数时按条数看，不看百分比。
7. **归因用的"要点在不在材料里"是字符重合度粗筛，不是语义判定**，用它的人踩过一次坑：最初的实现按纯字符 2-gram 算，英文/技术名词拆出的碎片（`at`/`ed`/`io`…）在任何技术文本里都成片出现，会把不相干内容判成 0.59 重合。现改为「中文 2-gram + 长度 ≥4 的英文整词」，并逐条打印重合度供人工复核；B/C 两类的边界条目（重合 0.5~0.6 的）已人工看过原文。
8. **标注与判定的两处修正均入档**：① 覆盖分母里的"干扰项"已移出（那类要点"答错方向才扣分"，不该计入必答）；② 1 条要点的措辞修订后其覆盖判定曾按"仅对原样要点沿用"的规则丢失，已单独补判恢复。修正后覆盖 **90%（155/173）**、历史事故层 67%。
