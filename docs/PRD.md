# 技术学习陪练 Agent - 产品需求文档



## 一、项目背景



开发者学习新技术时，通常面临以下问题：



- 资料分散、筛选成本高，需要跨平台手动搜集
- 官方文档以英文为主，术语抽象、缺乏上下文，阅读门槛高
- 学习路线不清晰，不知道该先学什么后学什么，容易迷失方向
- 知识点碎片化，缺乏体系化的整理和沉淀机制
- 与 LLM 对话获得的答案往往“一次即弃”，无法形成长期可复用的知识资产



本项目旨在构建一个 **具备“信息获取 → 知识理解 → 成果沉淀”完整闭环的智能学习陪练 Agent**，帮助开发者高效、系统地掌握一门新技术或框架。



## 二、用户画像



- **主要用户**：希望学习新技术的个人开发者、不了解如何高效获取资料的技术小白
- **使用场景**：学习新的编程语言（java、Go）、后端框架（如 Spring Boot 3）、前端框架（如 Next.js）、或 AI 应用框架（如 LangChain）
- **用户目标**：用最短的时间，从“不知道”到“能上手写一个可运行的最小项目”



## 三、核心功能模块



### 模块 1：智能资料收集（信息获取层）



**功能描述**：

用户输入一个技术主题（如“学习 Spring AI”），Agent 自动检索并聚合以下来源的资料：

- 官方文档（primary source）
- 官方 GitHub 仓库的 README、示例代码
- 权威技术博客（如 Martin Fowler、Baeldung 等）
- 社区高赞讨论（如 Stack Overflow、Reddit、Dev.to）
- 主流学习平台（如 YouTube 官方教程、Udemy 大纲参考）



**用户交互**：

用户输入 `/collect Spring AI`，Agent 后台执行资料爬取，输出一份 `materials.md`，包含：

- 资料清单（按来源分类，标注优先级）
- 推荐阅读顺序
- 已下载/缓存的文档本地路径



**核心流程**：

1. Agent 接收技术名称
2. 调用搜索工具（如 Tavily、Exa）获取相关链接
3. 调用网页抓取工具（如 Jina Reader、Firecrawl）提取页面正文
4. 对内容进行去重、质量评分（基于来源可信度、发布时间）
5. 生成本地缓存文件（Markdown 格式）
6. 输出资料清单和阅读建议



**输入输出**：

- 输入：技术名称（如 "LangGraph"）+ 可选的深度级别（入门/进阶）
- 输出：结构化的资料清单 + 本地缓存文件



**涉及的 Prompt / 提示词工程**：

- **资料筛选 Prompt**：要求 Agent 从搜索结果中按权威性、时效性、相关性进行排序，过滤低质量内容
- **阅读顺序生成 Prompt**：根据资料之间的前置依赖关系，生成合理的阅读序列

### 模块 2：定制化学习路线（规划层）



**功能描述**：

结合用户的当前水平（通过问卷或代码测验）和模块 1 收集的资料，生成一份**个性化、可执行的学习路线图**。



**用户交互**：

首次使用或切换技术时，Agent 会主动发起一轮“水平探测”：

- 你对该技术的熟悉程度（0-10 分自评）
- 你熟悉的相关技术（如学 Spring Boot 前，是否懂 Java、Maven）
- 快速诊断测验（3-5 道选择题/补全题，动态出题）



基于用户反馈，Agent 生成 `learning-roadmap.md`，包含：

- 学习阶段划分（如：环境搭建 → 核心概念 → 实战项目 → 进阶调优）
- 每个阶段的资料推荐（来自模块 1 的资料清单）
- 预估学习时间
- 里程碑检测点（完成一个小项目才算通关）



**核心流程**：

1. Agent 发起水平探测对话
2. 用户完成问卷 + 测验
3. Agent 结合资料清单，生成学习路线
4. 用户确认/修改路线，存入本地



**输入输出**：

- 输入：用户水平探测的对话记录
- 输出：`learning-roadmap.md` 文件 + 当前学习进度的状态跟踪



**涉及的 Prompt / 提示词工程**：

- **水平探测 Prompt**：引导 Agent 设计诊断问题，根据用户回答动态调整后续问题（类似自适应测验），并评估用户对前置知识的掌握程度，识别知识盲区
- **路线生成 Prompt**：根据水平评估结果和资料清单，生成分阶段的、可执行的学习路径，包含具体的学习目标和可检验的里程碑

### 模块 3：文档阅读辅助（理解层）



**功能描述**：

用户阅读官方文档时，可通过对话或直接输入文档 URL，获得以下辅助：

- 中文翻译（保留术语对照，不是机翻，而是有解释的意译）
- 核心概念的本质解释（用通俗类比 + 可交互的 Mermaid 图表）
- 重点高亮（哪些是必读核心，哪些是可跳过的边缘细节）
- 最小可运行示例（直接给出可执行的代码，并附带运行说明）
- 踩坑预警（常见错误、版本兼容性问题）



**用户交互**：

用户输入 `/read `[https://docs.spring.io/...\`，Agent](https://docs.spring.io/...`，Agent) 返回结构化的文档解读报告。



**核心流程**：

1. Agent 抓取文档页面内容
2. 通过 RAG 检索该文档的历史解读记录（如果有）
3. 调用 LLM 生成文档解读报告
4. 如果文档有多个版本，自动识别当前最新稳定版本
5. 生成可运行的“最小示例”（代码文件 + 配置文件）
6. 输出报告



**输入输出**：

- 输入：文档 URL（或上传的 PDF/HTML 文件）
- 输出：文档解读报告（Markdown 格式）+ 最小示例代码文件



**涉及的 Prompt / 提示词工程**：

- **文档解读 Prompt**：要求 Agent 对文档进行结构化拆解，包含**概要**（文档讲什么，解决什么问题）、**术语解释**（核心术语的本质解释 + 通俗类比）、**重点章节标注**（必读/选读/可跳过）、**核心流程梳理**（用 Mermaid 流程图表示）、**最小示例生成**（可运行的代码）、**踩坑预警**（从社区经验中提取）、**版本说明**（当前解读基于哪个版本，与旧版本的差异）
- **术语解释 Prompt**：结合用户选择的知识背景领域（如“电商系统”、“游戏开发”），用该领域的场景类比解释抽象概念。例如用户选“电商领域”，则用“购物车”类比“Session”，“订单状态机”类比“工作流引擎”

### 模块 4：学习成果沉淀（知识管理/记忆层）



**功能描述**：

每次学习结束后，Agent 自动将零散的知识点整理成结构化的个人知识库，支持版本管理和增量更新。



**核心流程**：

1. 一轮学习结束（用户说“今天就到这”或关闭对话），Agent 自动触发沉淀流程
2. 提取本次对话中的关键知识点（概念、代码片段、注意事项）
3. 检查是否与已有知识库内容冲突或重复，进行合并（版本化管理）
4. 生成/更新 `TechKnowledgeBase/[技术名]/[日期]-[主题].md`
5. 更新索引文件 `INDEX.md`



**输入输出**：

- 输入：本轮学习的对话记录 / 文档解读报告 / 最小示例代码
- 输出：新增/更新的知识库 Markdown 文件 + 索引文件



**涉及的 Prompt / 提示词工程**：

- **知识提取 Prompt**：要求 Agent 从对话记录中提取结构化的知识点，包含**概念名**、**本质解释**、**类比**、**代码示例**、**注意事项**、**参考资料链接**
- **增量更新 Prompt**：检测新知识是否与已有知识库内容重复、矛盾或互补，并决定是新增、合并还是替换，同时标记更新日期



----



### 模块 5：虚拟机陪练（执行层）【进阶功能，MVP 可暂缓】



**功能描述**：

Agent 不仅能“说”，还能“做”。它可以在隔离环境中帮你跑通示例代码、执行 Docker 命令、生成配置文件，并验证是否成功。



**核心流程**：

1. Agent 生成最小示例代码
2. 将代码写入本地临时目录（或沙箱容器）
3. 执行构建/运行命令（如 `mvn spring-boot:run`）
4. 捕获输出，如果失败则尝试自行修复（最多 3 次）
5. 成功后告知用户，并提供访问地址
6. 清理或保留容器供用户继续开发



**涉及的 Prompt / 提示词工程**：

- **错误修复 Prompt**：要求 Agent 分析报错日志，结合上下文（代码、配置文件、环境变量），给出修复方案并自主尝试修复。具体包含**日志解析**（提取错误类型、位置、关键信息）、**根因推断**（判断是代码问题、配置问题还是环境问题）、**修复策略生成**（如果是代码问题则修改代码，如果是配置问题则调整配置，如果是环境问题则提示用户安装依赖）、**最多重试 3 次**（每次修复后重新运行验证，3 次后如仍失败则向用户报告并请求人工介入）

### 核心技术栈（仅供参考）



| 层级 | 组件 | 可选技术 | 说明 |
| --- | --- | --- | --- |
| **Agent 框架** | 核心循环 | LangChain / LangGraph / 自建 ReAct Loop | 负责 Agent 的推理-行动-观察循环 |
| **工具标准** | MCP | Model Context Protocol | 统一管理工具，便于扩展 |
| **向量数据库** | 知识检索 | Chroma (本地) / FAISS / Milvus | 存储文档切片向量，用于 RAG |
| **Embedding 模型** | 文本向量化 | `text-embedding-3-small` / `BAAI/bge-m3` | 将文档和查询转换为向量 |
| **LLM** | 推理与生成 | OpenAI / Anthropic / DeepSeek / 本地 Ollama | 核心大脑，需要支持 Function Calling |
| **网页抓取** | 内容提取 | Jina Reader API / Firecrawl / `trafilatura` | 将网页转为 LLM 友好的 Markdown |
| **搜索工具** | 资料检索 | Tavily API / Exa API / 自建搜索代理 | 提供高质量的搜索结果 |
| **代码沙箱** | 安全执行 | Docker SDK / `agent-sandbox` | 隔离运行生成的代码（进阶功能） |
| **前端交互** | 用户界面 | Click (CLI) / VS Code Extension API / Streamlit | 按需选择 |



### 关键技术决策点



| 决策项 | 方案 A（简单） | 方案 B（专业） | 推荐 |
| --- | --- | --- | --- |
| Agent 框架 | 直接调用 LLM API + 手写循环 | LangGraph 状态机 | 先用 A，做复杂了再迁移到 B |
| 知识存储 | Markdown 文件 + 全文搜索 | Chroma + 向量检索 | 两者都保留，Markdown 作为人类可读的"源"，Chroma 作为检索的"索引" |
| 代码执行 | 直接在宿主机执行 | Docker 容器隔离 | MVP 用 A（明确提示风险），正式版必须用 B |
| 工具调用 | 硬编码工具函数 | MCP 协议 + 动态加载 | 逐步过渡到 MCP |

## 五、实现难度评估



### 总体结论



| 功能模块 | 实现难度 | 核心挑战 | 是否适合个人开发者 |
| --- | --- | --- | --- |
| 模块 1：智能资料收集 | ⭐⭐ (低-中) | 搜索结果质量筛选、网页抓取反爬 | ✅ 非常适合，AI Coding 可快速搭建 |
| 模块 2：定制化学习路线 | ⭐⭐⭐⭐ (高) | 精准的用户水平评估、动态规划 | ⚠️ 有挑战，"足够好"容易，做到"精准"很难 |
| 模块 3：文档阅读辅助 | ⭐⭐ (低) | RAG 检索质量、术语解释的准确性 | ✅ 非常成熟，有大量开源参考 |
| 模块 4：学习成果沉淀 | ⭐⭐⭐ (中) | 知识冲突检测、版本管理 | ⚠️ 基础版简单，完善版有挑战 |
| 模块 5：虚拟机陪练 | ⭐⭐⭐⭐⭐ (很高) | 安全的代码执行环境、错误自动修复 | ❌ 工程量大，建议延后或简化 |

## 七、风险与限制



| 风险 | 影响 | 应对策略 |
| --- | --- | --- |
| API 调用成本过高 | 无法长期使用 | 使用本地模型（Ollama）、缓存搜索结果、限制每次检索的链接数 |
| 网页抓取被封 | 无法获取资料 | 提供"手动输入资料链接"的 fallback 机制 |
| LLM 生成的解读不准确 | 用户学错知识 | 保留原文引用、提供多源交叉验证、用户在关键节点需要人工确认 |
| 知识库内容膨胀 | 检索变慢、上下文溢出 | 分层存储（近期高频知识在"热"区，远期知识在"冷"区），根据时间衰减权重 |
| 个人项目维护动力不足 | 烂尾 | 先做 MVP，验证自己每天都在用，再迭代；"先为自己做工具"心态 |

## 九、总结



这个项目**技术完全可行**，核心 RAG 和 Agent 工具调用部分非常成熟，适合个人开发者借助 AI Coding 工具快速实现。最大的"坑"在于两点：



1. **"自适应学习路线"要做到真正精准非常难**——建议先做一个"够好用的版本"，不要追求完美
2. **代码沙箱执行安全风险大**——建议 MVP 阶段不做，或者只做"生成代码 + 指导用户手动运行"的轻量版



**一句话建议**：先做一个 **"能帮你省时间的资料收集 + 文档解读 + 笔记整理工具"** ，让 Agent 成为你学习过程中的"自动化助手"，而不是"全能导师"。让它先跑起来，再用它来学更复杂的技术、完善它自己——这是一个非常有趣的"自举"场景。
